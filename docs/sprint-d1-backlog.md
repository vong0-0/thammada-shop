# Sprint D1: Discovery and brand direction

**Sprint Goal:** See the brand and the whole-system flow clearly, and confirm that the Phajay sandbox can be called for real.

## Capacity

Available time is about 6 hours a day for 6 days, with one rest day: 36 hours a week.

| Item | Hours |
|---|---|
| Total time | 36 |
| Scrum events (Planning, Daily, Review, Retro) | ~3 |
| Buffer for bugs, learning and interruptions (15 to 20%) | ~5 |
| **Plannable capacity** | **~28** |

Days longer than 6 hours count as extra buffer, not as planned work.

## Notes on specific tasks

**Task 1.** The Figma file already exists. Starter plan allows 3 pages per file, so the file uses 3 pages (Foundations, Flows & Wireframes, UI & Components) with sections inside them.

**Task 2 (spike).** Start the sandbox registration on day one. The approval time is unknown, so do tasks 3 to 8 while waiting. Record in a short note: what the API returns (QR format, expiry time, payment status values, error cases) and how the payment result is delivered back to the server (callback or other). Those answers shape the payment screens in Sprint D2. Documentation: https://payment-doc.lailaolab.com/v1

## Definition of Done for Sprint D1

- Every deliverable is saved in Figma or in this repo.
- The wireframes have been walked through from choosing a product to paying.
- The spike has a written summary of what the Phajay API returned.
- The Sprint Review is recorded as a short video.

## Sprint events

| Event | Plan |
|---|---|
| Planning (~1 h) | Confirm the Sprint Goal and the task list |
| Daily (5 min) | Write 3 lines: yesterday, today, blockers |
| Review (~30 min) | Demo the Figma work and the spike result, record a video |
| Retrospective (~30 min) | What went well, what did not, one thing to change |
